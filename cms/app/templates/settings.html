New devices

Applied when a device enrolls for the first time (POST /api/enroll). Re-enrolling a known device keeps whatever it has. A deleted group or playlist counts as none.

Remote updates

Set in /etc/projector-cms/env (restart the CMS to apply). Devices get these in every manifest; "Update player" on the Devices page installs the release below.

player release{{ update.release }}
PIPLAYER_PLAYER_RELEASE (tag, branch or sha)
auto update{{ update.auto }}
PIPLAYER_AUTO_UPDATE (off | nightly)
update window{{ update.window }}
PIPLAYER_AUTO_UPDATE_WINDOW (HH:MM-HH:MM, Pi local time)

Projector power

Set in /etc/projector-cms/env (restart the CMS to apply). Per-device control, mode and learned IR codes live on the Devices page; in auto mode the manifest tells the Pi when the projector should be on.

lead time{{ projector.lead }} min
PIPLAYER_PROJECTOR_LEAD_MINUTES: switch on this long before a schedule rule starts
idle-off delay{{ projector.idle }} min
PIPLAYER_PROJECTOR_IDLE_MINUTES: switch off once nothing has played for this long

Enrollment key

Baked into the flasher so a freshly flashed Pi registers itself on first boot (no login needed). Re-flashing a card re-enrolls the same device with its existing token.

Rotate if a card or flasher build is lost; devices already enrolled are unaffected.
